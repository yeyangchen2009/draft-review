中15 挂钟 **1 小时 37 分 55 秒**，但真正的活跃工作只有约 **57 分钟**——两个外部工具的**静默挂起**白白吃掉约 **41 分钟**：

|---|---|---|---|
| ① CDP 三浏览器并行冷启动 | 14 分 17 秒 | ≈2 分 | 图片文件 mtime 20:11；同性质第二批仅 **27 秒** |

"久"的主因不是工序多，而是**等待没有超时、进程没有心跳、挂起后整条时间线被堵死**。

## 已排除的嫌疑

- **机器睡眠**：System 日志 18:00–21:30 无 Kernel-Power 42/107、无 Power-Troubleshooter 唤醒记录；
- **代理问题**：当前 shell 与 git 均无代理配置，gh 直连；
- **headless 残留**：无 cdp-shot 进程残留，浏览器清理正常（现存 4 个 Edge 为日常窗口）；
- **工具内长轮询**：DevTools 端口超时 20s、默认 settle 3.5s，cdp-shot 本身没有长等待。

剩余解释：**外部进程/网络调用偶发半挂（TCP 无响应、并行冷启动竞态），而调用方既无超时也无输出，于是主流程干等**。这类问题不可预测，但可以让它**不阻塞**。

## 优化方案

### A. 让挂起不再堵路（直接治"久"，性价比最高）

1. **外部等待一律包超时**：`gh`/`node` 长命令外套 `timeout 180 …`（Git Bash 自带 coreutils timeout），超时即转后台或改主动轮询；
2. **长任务禁止静默**：输出写日志文件（不再 `>/dev/null 2>&1`），随时可 tail、可复盘——本次两个黑洞都因静默而零证据；
3. **CDP 单浏览器多景模式**：cdp-shot.js 新增 `--shots <json>`，一次冷启动、一次全滚触发 lazy，按多个 rect 连续截全部 5 景。消灭"3 个临时 profile 并行冷启动"的竞态（14 分 vs 27 秒的差异源），还顺带省重复 settle；
4. **eval watchdog**：浏览器内异步操作包整体超时，失败给明确错误而非挂住。

### B. 压缩活跃路径（57 → 45 分左右）

5. **构建 3 次 → 2 次**：
   - 图片 push 后用 `gh api contents` 确认已在 main，**直接建文章 issue**——已核实 Gmeek.yml 的 `actions/checkout@v4` 无固定 ref，issue 构建必 checkout 含图的最新 main，部署后图片即 200。**省掉全量重建**（也根除 dispatch 乌龙）；
   - 兜底保留：构建后 curl 图片，404 才补一次 rerun（零竞态下不会发生）；
6. **门户构建与 CDP 并行**：文章 issue 一创建拿到编号，立即编辑 #72 打勾（门户只需要可预测的 `/post/N` 链接，不依赖文章已上线）。门户自己构建的 2 分钟与 CDP 验收重叠，**省掉"最后再等一次构建"**；
7. **一键发布脚本** `tools/publish-post.py`：剥 frontmatter → 建 issue → 取新 run（核对 displayTitle＋时间窗）→ 限时 watch → curl 验证图/页。消除临场拼命令（本次 jq select 写错、静默重定向均源于此）；
8. **pre-flight 一键化**：裸他精确扫描（逐字符枚举＋豁免覆盖区间）与 check-md（strong 开闭、字面星号）合并为发布前单命令。

上一集，init 三十秒，台子搭好了。

不过你打开浏览器看看，舞台中间那行字写的是「Hello HyperFrames」——那是它的样板，不是你的东西。

这一集，我们就把样板请下去，摆上头一个真正属于你自己的片段。

动手之前，先把一个观念掰过来。

你平时在剪辑软件里做视频，片段怎么摆？鼠标按住，往时间轴上拖，拖到第几秒，松开。时间，是拖出来的。

HyperFrames 里没有这回事。它的时间，是你拿键盘，一个数字一个数字，写在 HTML 标签上的。

片段什么时候上场、待多久，就是标签上的两个数字，明明白白摆在那儿。

所以这一集真正要学的，不是新命令，是一个新习惯：时间，是写出来的。

哈喽大家好，我是叶扬。

打开 index.html，找到中间那行 h1。

它身上有三样东西，你盯住了：第一个，class 等于 clip；第二个，data-start 等于 0；第三个，data-duration 等于 10。

先说这个 class。clip，片段。你想让一个元素成为视频里的片段，就得给它盖这个章。没有这个 class，渲染器扫过页面，根本当没看见它——你字写得再大、颜色再鲜艳，也进不了成片。

剩下两个属性，就是时间。data-start 等于 0，从零秒上场；data-duration 等于 10，足足待十秒。

好，现在把标签里的字，换成你自己的标题。改字谁都会，不算本事，咱们玩点真的——让这个标题第二秒再进来，第六秒就走。

怎么写？data-start 改成 2，data-duration 改成 4。

2 加 4 正好 6，第六秒准时下场。

跑一下 npm run dev，你亲眼看看：开头两秒，空荡荡一个舞台；第二秒，标题出现；第六秒一到，干干净净，消失。

没有鼠标，没有拖动，就改了两个数字。

接下来，再加一个片段。

在标题下面写一行小字，当副标题。时间给它错开——data-start 等于 6，data-duration 等于 4。瞧见没有，标题前脚走，副标题后脚来，两个片段在时间轴上排得整整齐齐，谁也不碍谁。

那你肯定要问：要是故意让两个片段撞在一块儿，谁盖着谁？

咱们就试。再放一张卡片，时间跟标题完全重叠。刷新一看——卡片老老实实待在标题底下。

规矩有两层。第一层看网页本身：HTML 里谁写在后面，谁就盖在上面，这是浏览器几十年的老脾气。第二层，你想手动安排站位，就用 data-track-index，数字大的压数字小的。

不过上一集说过的话，这里再钉一遍：track-index 主要是给那个可视化的 Studio 排位置用的，真到渲染的时候，程序不读它。所以别跟它较劲，拿不准的时候，调整一下标签前后顺序，最稳。

到这儿你发现没有，这一集从头到尾，我没写过一行 JavaScript。

没有动画，没有脚本，纯 HTML 和 CSS——标题多大、什么颜色、摆中间还是摆边上，全是你写网页的那身老手艺。可就是这么一个静态页面，它已经是一条完整的视频：有舞台，有片段，有精确到秒的起止。

这就是 HyperFrames 的第一层功夫：先学会摆，再学会动。

摆完了，别急着渲染，先让机器替你看一眼。npm run check。

新手最容易栽的，就三个错，你记住：

第一，忘了 class 等于 clip——元素在网页上明明看得见，渲染器就是不认；

第二，时间写出界。舞台总共 data-duration 十秒，你片段 data-start 给个 8、duration 给个 4，8 加 4 等于 12，超出的两秒去哪儿了？check 直接给你拦下来；

第三，单位。标签上写的是秒，不是帧。十秒就是十秒，别填个 300 上去，那是五分钟。

check 过了，preview 里再肉眼走一遍——几点出现、几点消失，心里都对得上，这一集就算齐活。

不过你也看出来了，现在的画面，还是「活」不起来：标题不会飞进来，字不会一个个点亮，卡片也不会翻。

是谁管这些？下一集，整个系列最核心的一集。

我们要讲清楚，为什么 GSAP 的时间轴必须先暂停住，还得到 window.__timelines 那张表上报个到——渲染器才有办法「跳到任意一秒，画面立刻就位」。

灵魂在 seek。hf-04，我们接着来。

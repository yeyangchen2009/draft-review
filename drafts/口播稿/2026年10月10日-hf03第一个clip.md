上一集，台子搭好了。

可你打开浏览器看看，舞台中间那行字写的是「Hello HyperFrames」——样板，不是你的东西。

这一集，我们就把样板请下去，摆上头一个真正属于你自己的片段。

动手前先把一个观念掰过来：在剪辑软件里，片段是鼠标按住、往时间轴上拖出来的；HyperFrames 里没有这回事，时间是你拿键盘，一个数字一个数字写在 HTML 标签上的。

哈喽大家好，我是叶扬。

打开 index.html，找到中间那行 h1。

盯住它身上的三样东西，这一集就讲这三样——一个章，两个数字。

第一个是章：class 等于 clip。clip，片段。想让一个元素成为视频里的片段，就得盖这个章。没有它，渲染器扫过页面当没看见，字写得再大、颜色再艳，也进不了成片。

剩下两个是数字：data-start 等于 0，从零秒上场；data-duration 等于 10，待十秒。什么时候进、什么时候走，全在这两个数里，明明白白。

好，现在把标签里的字换成你自己的标题。改字不算本事，咱们玩点真的——让标题第二秒再进来，第六秒就走。

怎么写？data-start 改成 2，data-duration 改成 4。2 加 4 正好 6。

跑 npm run dev，亲眼看看：开头两秒舞台空荡荡；第二秒标题出现；第六秒一到，干干净净，消失。没有鼠标，没有拖动，就改了两个数字。

再加一个片段。标题下面写一行小字当副标题，时间错开——data-start 等于 6，duration 等于 4。标题前脚走，副标题后脚来，两个片段在时间轴上排得整整齐齐。

那你肯定要问：要是故意让两个片段撞一块儿，谁盖着谁？

试一下。再放一张卡片，时间跟标题完全重叠。刷新一看，卡片老老实实待在标题底下。

规矩就一条，记住：**HTML 里谁写在后面，谁盖在上面**——这是浏览器几十年的老脾气，渲染的时候也认这个。想调先后，挪标签顺序最稳。

你可能在别处见过 data-track-index 这个属性，这里说清楚：它是给可视化的 Studio 排轨道显示用的，渲染成片时程序根本不读。所以别拿它当控制层叠的开关。

到这儿你发现没有，这一集从头到尾，我没写过一行 JavaScript。

标题多大、什么颜色、摆中间还是边上，全是你写网页的那身老手艺。可就是这么一个纯静态页面，它已经是一条有精确起止、随时能渲染的视频。

零行脚本，先出片子——这是 HyperFrames 的第一层功夫：先学会摆，再学会动。

摆完别急着渲染，先让机器替你看一眼：npm run check。

新手最容易栽的三个错，它都替你盯着：忘了盖 clip 这个章，元素在网页上看得见、渲染器不认；时间写出界，片段的结束点超过舞台总时长；还有单位，标签上写的是秒不是帧——习惯按帧想的人最容易栽，想让片段待三秒，抬手填个 90，可在这儿 90 是一分半。

check 过了，preview 里再肉眼走一遍，几点出现、几点消失都对得上，这集就算齐活。

不过你也看出来了，现在的画面还「活」不起来：标题不会飞进来，字不会一个个点亮，卡片也不会翻。

是谁管这些？下一集，整个系列最核心的一集。

我们要讲清楚，为什么 GSAP 的时间轴必须先暂停住，还得到 window.__timelines 那张表上报个到——渲染器才有办法「跳到任意一秒，画面立刻就位」。

这一集的主题，恰好是「别用眼睛看，让机器先看」——教观众跑 check，让自动化守门员把错误拦在渲染之前。结果有点反讽：check 零错误、文字对比度六十四比六十四全过 WCAG AA，机器把门把得无懈可击；可等成片出来做二轮复查（制作侧叫 F2），发现念白里有两处克隆音色自己念错的字，而负责自动验音的那台机器（语音识别 ASR），恰恰听不出来。

这篇复盘记录 hf-05《别用眼睛看》从分镜到发布候选版的全部新教训：为什么短了 54 秒的片子，渲染反而比上一集贵；写分镜时 check 抓到的两个真 bug；F2 怎么用 40 个画面点和 24 段高危音，拼出 164.8 秒的听审合集；以及本集最花心思的部分——两处念白错怎么被坐实、怎么被叶扬的耳朵拍板、最后怎么不动视频流就外科修好。

## 一、9 分 12 秒、17 幕、301 句，渲染反而更贵

先报账。终片 552.500 秒（9 分 12 秒），17 幕（sc-open 到 sc-bye），301 句逐字字幕，2096 字口播——叶扬拍板口播不压缩、铺满整个时长。check 结果是 **0 error**，剩下 19 条全是基线 warning（3749 行的文件过大提示、17 处轨道过密、17 处嵌套过深，跟上一集同款接受项），文字对比度 **64/64 全过 WCAG AA**。字幕时间偏移逐片实测的惯例照走，measure_offset 这次量出 **time_offset 0.29**（43/66 个 onset 配对，中位数 +293.1 毫秒、均值 +263.8，系列五片 0.28/0.37/0.29/0.30/0.29）。

片子比 hf-04 短 54 秒，渲染却更贵：总墙钟 **68 分 59 秒**，上一集是 52 分 03 秒。差别主要在帧格式。这集嵌了大量 1600×920 的终端屏录，默认 jpg 帧在等宽字体边缘会渗出色度噪点，叶扬给 render 加了 `--video-frame-format png`，全部 **16575 帧**走无损 PNG 落盘。分阶段账：compile 14.4 秒、capture 66 分 21.5 秒（上一集 jpg 帧是 46 分 56 秒）、assemble 48.8 秒——机时税几乎全在 capture。值得一提的是本片总帧数 16575 比上一集的 18195 还少约 9%，截图时间却多了约 20 分钟，无头 Chrome 逐帧 seek、摆位、截图之外，单帧 PNG 的落盘成本是主要增量。

这笔账把一条规矩压得更死：**改一句文案、挪一个元素，重烤一次就是 69 分钟起步。** 所有文字复查、念白核对、布局目验，必须全部压到 render 之前。后面两处音频补丁之所以值得细讲，正是因为它们最终没有惊动这 69 分钟。

## 二、render 之前，机器先抓了两个真 bug

这集讲「让机器挑错」，制作过程也被同一套哲学救了两次：分镜页面在 check 阶段就被 StaticGuard 抓出两个靠肉眼很难发现的问题。

**第一个是 GSAP 的 className 陷阱。** 六关递进高亮原本写的是 `tl.to(el,{className:'+=on'})`，预期像 jQuery 那样给元素**追加**一个 on 类。接触表抽帧一看全错：第 72 秒该亮的 Lint 还是透明的，第 88 秒后三关反而全亮。查证后发现，当前版本 GSAP 对 className 的处理是**替换**——元素原有整组类被换成孤零零一个 `on`，六关各自的颜色类丢了，高亮自然乱套。改法是删掉 `.on` CSS 规则，用 gateAt() 直接补间 backgroundColor、borderColor、color；属性补间对任意 seek 点都能还原，恰好也符合系列反复强调的 seekable 原则。

**第二个是 StaticGuard 对注释语法的硬 error。** 分镜卡的可见正文里出现了一段 `/* …… */`，check 立刻报 visible_markup_comment：HTML 的注释只能写 `<!-- …… -->`，CSS/JS 的注释语法错放进了可见正文。更值得记的是它的**连坐效应**——只要存在 1 个 error，后续 Layout 阶段干脆不采样，终端吐出一句很唬人的 `0 issues across 0 sample(s)`：零问题不是因为没问题，是因为压根没查。这跟正片里那句「真调了不存在的函数，控制台 page_error，后面所有的绿都不可信」几乎是同一条道理，叶扬在制作侧结结实实撞了一次。注释全删，再 grep 确认其余 `/* */` 只藏在 style/script 里，过闸。

## 三、F2：40 个画面点，24 段声音

成片之后的 F2 分视觉、正音两条线。

视觉线用接触表：从终片抽 40 个规定时刻——intro 接合 4 点、17 幕各取一个中点、9 个关键状态帧（闸门递进、Contrast 红灯、text_occluded、#sut 三警告等）、5 处 video→freeze 接缝前后各一帧——缩成两张 6×4 表全部目验。三张代表性的画面：

![F2 目验样本·全绿：Runtime 0 errors 0 warnings，Layout 0 issues across 9 samples，Motion 干净，Contrast 10/10 text checks pass WCAG AA，Snapshots disabled，绿色 Check passed](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf05-review/hf05r01-all-green.png)

视觉线也复用上一集的分层排查法。接触表上一处 video→freeze 接缝两侧，终端窗疑似有十几像素跳位；单帧放大双比后，几何完全一致（窗口四边坐标左 53/顶 209/右 1173/底 840），差异只是命令从 `@0.8` 敲到 `@0.8.107 c` 的打字中间帧，完成帧正常演进——是动作段的自然变化，不是穿帮。

抽帧工艺这集也换了新打法。552.5 秒的片抽 40 点，纯 output seeking（`-ss` 写在 `-i` 之后）每个点都从头解码，跑了 14 点就 5 分钟超时；改成两阶段——先 input seek 到 t−1.5 秒落到最近关键帧（粗定位），再在这 1.5 秒内做 output seek（精定位），40 点秒出，时间精度仍由第二跳保证。

正音线是本集重点。先列 24 个高危点：几百行的「行」、三处 děi、重叠 chóng、挑 tiāo、深蓝灰、色值逐字符、rgb 数字、WCAG、糊弄 hùnong、帧/暂/碍、三条英文规则名（timeline_element_missing_timing / clip_ends_past_root_duration / text_occluded）、npx、at、横杠横杠、error level，以及为骗读做的改写（量→测、数→算节拍、待→停五秒）。按 raw.json 的 segment 时间戳切句，每句前后留 0.5 秒、句间插 0.8 秒静音，拼成 **164.8 秒**合集，配一份逐句索引。

whisper 双语转写负责客观排雷：三条蛇形规则名按英文词念对了（转写里能认出 Mission Timing / RudeDuration / Acluded），npx/at/--shot/error level、9 处「行」的预处理（8 处改写避开、仅「几百行」借「航」）、测/算节拍/停五秒全部落实。但 whisper 对**同音字和声调**判不了——正确与错误的 děi 都会被转写成「得到」，整读的 wàigé（外格）和逐字母 W-C-A-G 也都会被勉强映射成「外格」。24 段里真正要交给耳朵的，只剩 5 个 ASR 不可判的点。

这条线还踩了 concat demuxer 两个坑：`-c copy` 切出来的 wav 头不标准会被拒绝（退出码 4294967294），切段统一重编成 pcm_s16le、24000Hz、mono；listfile 里的相对路径按 listfile 自身所在目录解析，写绝对路径才成。

## 四、第一处念错：WCAG，六版借音全败

进入正题。第 232.42–232.76 秒那句「这是无障碍标准 WCAG 的口径」，克隆音色把 WCAG 当成一个可发音的英文词，整读成双音节 wàigé（转写「外格」）。

先客观坐实，不靠耳朵吵架。量这一段的词长：232.42–232.76 共 **0.34 秒**，这是一个双音节单词的时长；若真按字母逐个念 W-C-A-G，四个字母名这一段至少要约 1 秒。词长已经宣告了读法。

坐实之后是治。克隆服务内部有文本归一化加发音词典，叶扬连试六种写法想骗出逐字母读：

| 写法 | 归一化后结果 |
|---|---|
| 空格 `W C A G` | 整读 外格 |
| 点号 `W.C.A.G.` | 只拆成 WC-AG 两段 |
| 顿号 `W、C、A、G` | 整读 外格 |
| 英文逗号 `W,C,A,G` | 整读 外格 |
| 全角 `ＷＣＡＧ` | 整读 外格 |
| 句号断词 `W。C。A。G。` | 连听可逐字母分辨，采用 |

孤立合成 W、C、A、G 单字母也试过：C、A 的 RMS 只有 0.008（约 −45dB，贴着底噪），单字走的是另一条不稳定的处理支路，ASR 还会把这些低电平音节强解成 Thank you、See you soon，更不能当证据。

眼看要在第七、第八版写法上继续钻牛角尖，叶扬听完已有版本一锤定音：句号断词那一版，连起来能一个字母一个字母地分辨，**「不要再纠结了」**。

这一条的方法论分量比修复本身重：**缩写是 TTS 词典的硬领地**。客观测量（0.34 秒词长）只能坐实「错」，「这样能不能接受」的最终判据是耳朵——而且是克隆源本人的耳朵，不是 ASR 的转写文本。

## 五、第二处念错：被高频词带跑的「得到」

另一处在第 157.68–159.78 秒的半句「它得到第十三秒才走」。语义上这个「得」是「必须」，要念 děi（必须到第十三秒才离场）；可「得到」是超高频常用词，词典优先把它当一个整词，按 dédào（获得的得，阳平）念了。成片里三个 děi 点（都得画像素、黄字得逐条读完、得到第十三秒），唯独这一处被带跑。

同样先建客观判据。拿已被叶扬确认念对的得 2、得 3 和念错的得 1 做基频（f0）对照：正确的半上声在 děi 这个音节上表现为后半程单调下行，得 2、得 3 的 f0 后半都跌了约 **11%**；错误的得 1 中段有一个阳平特征的抬升峰。短字只有三四个基频周期、单看不可靠，但有了两个已确认的正确样本当锚，声调差异是看得出来的。

随后合成三个候选：① 逗号破词「它得，到第十三秒才走」；② 「它得等到第十三秒才走」；③ 「它得要到第十三秒才走」。叶扬逐版听完，裁定三版念的都是 děi，「没问题」。

最终选①，关键在**字数**：逗号只负责制造停顿、骗词典把两个字分开识读，书面上仍是「它得到」三个字——与原句同字数，字幕逐字高亮零错位。②③ 都多一个字，声音更长，会把后面所有 cue 的音画对齐整体往后挤，发音对了也不能用。

## 六、音频外科：视频流一帧不动，90 秒收工

两处都只改音轨，绝不动烤了 69 分钟的视频。补丁脚本从原始母带一次重建整条音轨，沿用上两集 patch_hang_yin 的句级外科工艺：

1. **定窗**：沿 20ms RMS 包络，在**句子之外**的停顿谷底找补丁边界（半窗 0.12 秒；左边界向前搜、右边界向后搜）。第一版在中心点两侧双向搜，找到句内的谷把窗缩窄了；改成只往句外搜才对——窗必须从外面完整包住整句。
2. **对齐时长**：新合成的整句经 atempo 微调到窗长。WCAG 窗 230.220–237.020（窗长 6.800 秒，补丁 6.765 秒），atempo **0.9949**；得到窗 157.660–159.880（窗长 2.220 秒，补丁 2.205 秒），atempo **0.9932**。两处变速都不到 1%，人耳不可觉。
3. **缝合**：两端 12 毫秒余弦 crossfade；脚本断言「窗外采样逐样本不动」，补丁只在窗内生效。
4. **重封**：`-map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -movflags +faststart`，视频流原样拷贝，只重编音频。

于是有两版终片：未补丁的 hf-05-yeyang-cover.mp4（40,633,460 字节）留档，发布候选 **hf-05-yeyang-cover-patched.mp4**（33,580,021 字节，32.0MiB），与正片等长 552.5 秒；视频流零重编码、逐包拷回，动的只有音轨。两段补丁在成片里的实际听感，叶扬逐句切出来听过，确认通过。

## 七、这集新长出来的四条规矩

第一条，**机器把门有边界**。check 守得住结构、报错、遮挡、对比度，守不住 seekable（上一集计数器一路全绿、多个渲染器却给出不同答案），也守不住自家 TTS 的念白；而 ASR 对同音字、声调的「听不出」，绝不能被误读成「没问题」。F2 的人耳是不可替代的最后一道。

第二条，**缩写查锁死，高频词防带跑**——TTS 的两座暗礁。英文缩写先怀疑发音词典，六种写法都撬不开就认，换句号断词；常用字拼成的高频词（如「得到」）警惕被当整词念，用标点破词时务必保持原字数，否则赢了发音、输了字幕对齐。

第三条，**最贵的工序绝不用于返工**。69 分钟的 PNG capture 倒逼所有可改项——文案、布局、念白——全部左移到 render 之前；真出了问题，优先在母带音轨上做 atempo 不超过 1%、12 毫秒 crossfade、视频流 copy 的句级外科，而不是重烤整条片。

第四条，**客观证据负责坐实与排除，人负责拍板**。0.34 秒词长、f0 后半 −11%、RMS −45dB 电平、atempo 0.9949/0.9932，这一条证据链让讨论不靠感觉；但「这样能不能发」的最终决定，由耳朵的主人一句话定。自动化最好的位置，是把选择空间收窄到几个有据可依的候选，再把决定权规规矩矩交还给人。

正片结尾那句话是：机器能判的交给机器，好不好看、节奏对不对、包袱响不响——那是创作者的事。制作这一集的过程本身就是注脚：让机器把 301 句里能自动验的全部验完，最后两处它验不了的错，由叶扬用耳朵守了下来。

下一集给片子加声音、加画面素材：音频文件找不到、媒体 id 对不上，这些在 Lint 关就是硬错误，根本走不到渲染那一步——又可以让机器先看了。

上一集，叶扬用一条 `init` 命令把项目架子立了起来：舞台 `#root`、片段 `clip`、暂停的 GSAP 时间轴，六文件样板一样不缺。可架子立好之后打开浏览器，舞台中间还摆着那行样板文字——`Hello HyperFrames`，它是脚手架的，不是你的。

这一集，把样板请下去，做头一个真正属于自己的片段。做之前，先掰一个观念。

## 一、先掰观念：时间不是拖出来的，是写出来的

用剪辑软件做视频，片段是怎么来的？鼠标按住素材，往时间轴上一拖——几点上场、待多久，全在这一拖里了。这是绝大多数人对「剪视频」的肌肉记忆。

HyperFrames 里没有这回事。

![左框：剪辑软件里，片段是鼠标按住往时间轴上拖出来的；右框：HyperFrames 里，时间是写在 HTML 标签上的](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf03/hf03-concept.png)

*两张卡片对照：左边是旧手艺，右边蓝框是新规矩——拿键盘，一个数字一个数字地写*

在这儿，时间不是拖出来的，是拿键盘一个数字一个数字写在 HTML 标签上的。听起来笨，但这正是它后面一切能力的地基：时间成了纯文本，就能被搜索、被 diff、被 AI 逐字审阅，也能被渲染器帧帧精确地算出来。所谓「Write HTML. Render video.」，落手的第一处就在这里。

观念掰完，打开 `index.html`，找到舞台中间那行样板 `h1`。

## 二、一个章，两个数字

盯住标题标签身上的属性，规矩一共就三样：

![Notepad++ 中标题标签的属性：class="clip"、data-start="0"、data-duration="10"](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf03/hf03-attrs.png)

*真实录屏定格：第 39 行就是样板标题，底部注解写着两个数字各管什么*

```html
<h1 class="clip" data-start="0" data-duration="10">Title</h1>
```

**一个章**：`class="clip"`。clip，片段。想让一个网页元素成为视频里的片段，就得盖这个章。没有它，渲染器扫过页面时当没看见——字写得再大、颜色再艳，也进不了成片。这是新手头一个常栽的坑：样式调了半天，渲染出来一片空，十有八九是忘盖章。

**两个数字管生死**：

- `data-start="0"`——几点上场。0，就是从零秒进场；
- `data-duration="10"`——待几秒。待满十秒，干干净净下场。

什么时候进、什么时候走，全写在这两个数字里。想知道一个片段在第几秒出现，不用打开任何面板，读标签就行。

旁边还跟着一个 `data-track-index="0"`，先混个脸熟：它只给可视化 Studio 的时间轴分轨道、排显示用，**渲染成片时程序根本不读它**，别拿它当开关。至于真正的层叠谁说了算，后面马上有实锤。

动手改东西前，叶扬还做了件家务事：样板默认从网上的 CDN 加载 GSAP，他把库下载到本地，标签里的地址换成本地一个 `gsap.min.js`。好处两条：断网也能渲染；版本钉死在本机，上游再怎么升级，都带不跑你的成片。

## 三、玩点真的：第二秒进来，第六秒走

家务事做完，开始动样板。

让标题第二秒再进来、第六秒就走。两个数字一改：`data-start="2"`、`data-duration="4"`——2 加 4 正好 6。标签里的文字也顺手换成自己的：「我的第一个片段」。

![时间轴 0 到 10，金色段落标着 2–6；下方公式 data-start="2" 加 data-duration="4" 等于第 6 秒走](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf03/hf03-time.png)

*开始与时长是一道加法：2 加 4 等于 6，出场时刻自己算出来*

回到浏览器，刷新，点 Preview 中间那个 Play：开头两秒舞台空荡荡，第二秒标题进来，第六秒一到消失。没有鼠标拖动，就改了两个数字。

一个片段不过瘾，再加两个。想在画面里自由摆位置，先给定位一个锚——在 `#root` 上加一句 `position: relative;`，里头的元素才好按它定位。然后把两张「脸」先画进样式里：一张琥珀色大字的卡片，一行灰色小字的副标题。没有任何新语法，都是普通 CSS。

卡片的时间故意捣乱：`data-start="3"`、`data-duration="2"`，也就是第 3 到第 5 秒。标题是 2 到 6，卡片是 3 到 5——故意撞个满怀。

为什么故意撞？为了亲眼看看，网页元素挤在一起时，谁盖在谁上面。

## 四、谁盖谁：HTML 里后写的，盖在上面

注意卡片这个标签写在哪儿：写在标题标签的**后一行**。

![Notepad++ 第 58 行是卡片、第 59 行是标题；底部金色一行写着「HTML 里后写的，盖在上面」](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf03/hf03-stack.png)

*真实代码：卡片 div 在标题 h1 的上一行——这是 Alt+Up 之后的终态，初始时顺序相反*

浏览器有个几十年的老脾气：HTML 里谁写在后面，谁就盖在上面。卡片写在标题后一行，它就盖在标题上。

这件事视频里只演示了现象，图文可以把底层原因讲透。叶扬用 CDP 查过运行时的真实样式，实锤是这样的：**HyperFrames 运行时会给所有 `.clip` 元素统一注入 `position: absolute; z-index: auto`**——你在源文件里写不写定位都一样。于是层叠规则退化成最朴素的一条：大家都是定位元素、`z-index` 又都是 auto，谁后出现在 DOM 里，谁就盖在上面。而前面说的 `data-track-index`，在这个环节根本不参与计算，它只管 Studio 界面的轨道摆位。

所以别按「定位元素盖静态元素」那套教科书直觉去猜，渲染器手里只有一条规矩：**DOM 顺序**。

想反过来怎么办？不用跟 `z-index` 较劲。Notepad++ 里光标点到卡片那行，`Alt` 加 `↑`，整行提走：

![Alt 加向上箭头之后，卡片行提到标题行之上；注解：标签顺序一换，上下立刻翻转](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf03/hf03-flip.png)

*快捷键 Alt+Up 移动整行；第 58 行的卡片已经压到第 59 行标题的前面*

标签顺序一换，画面上下立刻翻转——标题盖回卡片上面。调层叠最稳的办法，就是直接挪标签顺序，一个属性都不用加。

最后放副标题：`data-start="6"`、`data-duration="4"`，标题第六秒前脚走，它后脚来，时间上排得整整齐齐，互不打架。

到这儿回头盘点：标题多大、什么颜色，卡片摆哪、谁盖着谁，每个元素几点进几点走——从头到尾全是写网页的老手艺，**零行 JavaScript**，可这么一个纯静态页面，已经是一条有精确起止、随时能渲染成 MP4 的视频。先学会摆，再学会动；动起来的事，下一集才碰。

## 五、摆完别急着渲染：先让机器替你看一眼

新手做片子，摆完就想点渲染。叶扬的习惯是先跑一条命令：

```bash
npm run check
```

忘盖章的、时间写出界的（比如一共十秒，片段从第 12 秒才开始）、把秒当帧抬手填个 90 上去的——这些新手常栽的坑，它全替你盯着。

咱们这页也跑一下。红了：

![终端里 check 报红：content_overlap，卡片和标题两块文字重叠；Fix 行给出两个修法；Check failed](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf03/hf03-check-fail.png)

*红叉定位到第 3–4.88 秒：content_overlap，两块文字重叠、可能没法读*

报错说得毫不含糊：`content_overlap`——第 3 到第 5 秒，卡片和标题撞在一起，两块文字重叠，可能没法读。别急着辩解，看它下面那行 **Fix**，连怎么改都替你写好了，一共两条路：

1. 给每块文字各自的地盘（错开时间或位置）；
2. 如果这是你**故意**做的层叠，就在标签上盖个章声明一下：`data-layout-allow-overlap`。

这次重叠本来就是设计好的——要的就是卡片压标题那一下。那就按它说的，在卡片标签上加这个属性。

再跑一次，绿了：

![同一个终端：Runtime、Layout、Motion 全 0 错误，Contrast 4/4 过 WCAG AA，Check passed](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf03/hf03-check-pass.png)

*四项检查全绿：运行时、布局、动态零问题，对比度四块文字全过 WCAG AA*

运行时零错误，布局零问题，动态零错误，对比度四块文字全过 WCAG AA——`Check passed`。

看懂这个流程没有：**check 不是拦路虎，是守门员**。它不反对重叠，它反对的是「没打招呼」的重叠。你确认这是故意的，就拿属性明明白白告诉它，它立刻放行。把机器的判断和人的意图分开——机器负责发现所有可疑，人负责声明哪些是设计——这套分工，本身就是很「agent 时代」的写法。

过了 check，再到 Preview 里肉眼走一遍：几点出现、几点消失、谁压着谁，都对得上，这集就算齐活。

## 下一篇

三个片段、一组时间数字、一次层叠翻转、一轮红了又绿的检查——第一个真正属于自己的 clip 就这么落地了。全程没写一行脚本，用的全是 HTML 和 CSS 的老手艺，只不过每样东西身上多了几个管时间的属性。

不过你也看出来了，现在的画面还「活」不起来：标题不会飞进来，字不会一个个点亮，卡片也不会翻。是谁管这些？下一集是整个系列最核心的一集：为什么 GSAP 的时间轴必须先暂停住，还得到 `window.__timelines` 那张表上报个到，渲染器才有办法「跳到任意一秒，画面立刻就位」。

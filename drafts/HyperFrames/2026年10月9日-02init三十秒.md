上一篇叶扬带着大家认识了 HyperFrames——写一个网页，它给你渲染成视频。认识完了，该动手了。

不过别急着写代码。做任何项目，头一件事都不是埋头就干，而是先把架子搭起来。盖房子得先浇框架、立承重墙，后面的砖才知道往哪儿砌；写软件也一样，目录怎么分、文件各管什么、流程走哪几步，架子立对了，后面一路顺；架子立错了，越写到后面越拧巴。

HyperFrames 早就替人把这一步想到了：一条命令，三十秒，还你一个立刻能用的项目。这一篇就看看这三十秒里，它到底立下了哪些规矩。

## 一、命令叫 init：跟上一个项目名

这条命令叫 `init`，initialize，初始化。格式不复杂——命令后面空一格，跟上你想起的项目名：

```bash
npx --yes hyperframes@0.8.107 init demo
```

叶扬起了个最朴素的名字，`demo`，跑给人看。

![init 跑完：demo 目录已创建，六文件清单直接打在终端上](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf02/hf02-init.png)

*终端里「Created demo/」下面框出六个文件，随后 Studio 自己跑了起来*

它跟常见的脚手架不太一样。不少工具一上来先连环提问：用不用这个框架、装不装那套模板、配置选 A 还是 B，新手往往还没开写就被问懵了。HyperFrames 的 `init` 几乎不问问题，噼里啪啦几下，一个完整的项目就生成好了，还顺手帮你把本地 Studio 起起来——上图最后那几行绿字，`Studio running`，预览服务已经在本地端口上待命。

## 二、满打满算六个文件，挨个认脸熟

进到生成的目录里瞧瞧，文件不多，满打满算，六个。

但这六个文件，没一个是凑数的。叶扬在视频里先带着挨个认了个脸熟。

![六个文件的清单：主角 index.html，周围五个配角](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf02/hf02-six-files.png)

*定格的终端缩到左侧，右侧六行清单：前四个金色描边，最后两个蓝色描边*

逐个看：

| 文件 | 角色 | 管什么 |
|---|---|---|
| `index.html` | 绝对主角 | 将来那条视频，说到底就是这一个网页 |
| `package.json` | 快捷命令 | 里头藏着四条 `npm run` 命令 |
| `meta.json` | 项目身份证 | 记着项目的名字和出生时间 |
| `hyperframes.json` | 工程配置 | 素材放哪儿、要不要自动代理之类 |
| `CLAUDE.md` | AI 说明书 | 写给 AI 编程助手看的项目规矩 |
| `AGENTS.md` | AI 说明书 | 内容和 CLAUDE.md 几乎一模一样 |

最后这两个值得多说两句。`CLAUDE.md` 和 `AGENTS.md`，一个写给 Claude 这类带项目说明约定的助手，一个写给通用的 AI agent，内容几乎一模一样——这个项目里什么能做、什么不能做、流程怎么走，规矩全写在里头。你让 AI 帮忙干活，它一进门，先读这个。人定规矩、机器执行，规矩落在文件里而不是靠嘴交代，这本身就是「Built for agents」的味道。

脸认完了，真正的门道在主角 `index.html` 里。

## 三、舞台 stage：最外层那个 id="root" 的 div

不知道你平时做视频，时间是怎么安排的——在剪辑软件里，是拿鼠标把片段拖到时间轴的某一秒。可在 HyperFrames 这儿，时间不是拖出来的，是直接写在 HTML 标签上的。

打开 `index.html`，先看最外层这个 `div`，`id` 叫 `root`。它就是整个项目的**舞台**，英文叫 **stage**。

![舞台身上的四个关键属性](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf02/hf02-stage.png)

*代码卡五行：标签头加四个 data-* 属性，当前高亮到 data-width*

舞台身上挂着四个关键属性：

```html
<div id="root"
     data-composition-id="main"
     data-width="1920"
     data-height="1080"
     data-duration="10">
```

逐个翻译：

- **data-composition-id="main"**——给这一整段合成起个名字，叫 `main`。一个网页里可以有好几段合成，靠名字区分；
- **data-width / data-height**——声明画布有多大，1920 × 1080，标准全高清；
- **data-duration="10"**——这一整段合成总共十秒。

舞台有多大、演多久、叫什么名字，一个标签全声明了。

## 四、片段 clip：时间是 DOM 的属性

舞台搭好，里头上场的，才是一个个具体的片段，英文叫 **clip**。

比如脚手架自带的这个 `h1` 标题：

![一个 clip 的完整写法：class 加两个计时属性](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf02/hf02-clip.png)

*代码卡四行：h1 标签头、data-start、data-duration、标题内容*

```html
<h1 class="clip" data-start="0" data-duration="10">Title</h1>
```

翻译成人话：这个标题带着 `class="clip"`，从零秒开始上场，一直待到第十秒。

注意到没有——它**什么时候出现、待多久，全是标签上的一个数字**。这就是 HyperFrames 跟剪辑软件最不一样的地方：时间，是 DOM 的属性。想知道一个片段在第几秒上场，不用读工程文件、不用看时间轴面板，查标签上的数字就行。这对人是直观，对 AI 就是可检索、可修改、可核对的纯文本。

旁边还经常能看到一个属性，`data-track-index="0"`。它管轨道：可以把它想成舞台上的站位层数，数字大的盖在数字小的上面，两个片段撞在一块儿，谁在前谁在后就看它。

不过有句实话要讲：这个 `data-track-index` 主要是给可视化的 Studio 界面排轨道位置用的；真到渲染的时候，程序压根不读它。所以这会儿，只要知道「它代表轨道」就够了。

## 五、动画谁管：GSAP 与那个 paused

静态的位置和时间都有了，动画谁管？看 `index.html` 最底下那一小段脚本。

它用 **GSAP**——一个老牌网页动画库——建了一条 **timeline**，时间轴。代码很短，重点盯一个词，`paused`：

![GSAP 时间轴的创建：paused: true](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf02/hf02-paused.png)

*代码卡三行，paused: true 正在高亮*

```js
const tl = gsap.timeline({
  paused: true
})
```

这条时间轴刚建出来，是**先暂停住的**，不会自己往下跑。

这就有点反直觉了。做动画不就是让它动起来吗，为什么一上来先暂停？答案紧接着就揭晓。

## 六、登记到一张表，渲染器靠 seek 跳帧

时间轴建完、暂停住，脚本紧接着做了两件事：把它登记到 `window.__timelines` 这张表里，登记的名字还是那个 `main`；而时间轴本身，随时等候被人「拨」到某一秒。

![登记与跳帧：注册到 window.__timelines，tl.seek(t) 直达目标秒](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf02/hf02-seek.png)

*代码卡三行：第 1 行注册，第 3 行 seek 跳到那一秒*

```js
window.__timelines["main"] = tl
// ……
tl.seek(t) // 跳到那一秒，画面立刻就位
```

为什么非要「先暂停」，还得「登记」呢？因为这样一来，渲染器想知道第几秒的画面，根本不用从头播放——只要从 `window.__timelines` 里取出这条时间轴，让它直接 `seek`，跳到那一秒，画面立刻就位。

上一篇叶扬留了个扣子，说「跳到任意一帧」是 HyperFrames 的灵魂。看到这里大概能摸到边了：**舞台、片段、时间轴全是网页里可寻址的对象，任意一秒都能被直接点到、直接画出来**，不用等、不用演、没有现场。渲染器因此可以一秒 30 帧、帧帧精确地算。至于 seek 背后具体怎么做到帧帧一致、为什么逐帧跳还能保证状态不乱——那是第四集专门要讲的内容。

顺带一个实战坑：在这种逐帧 seek 的渲染方式下，GSAP 的 `addClass` 是不能用的——跳帧时类名的增删没法可靠还原。叶扬自己的分镜脚本里，动画一律直接设置内联样式，把动画状态也变成「任意 seek 点都能确定还原」的东西。

## 七、回到 package.json：四条命令就是主流程

`index.html` 看完，再回到 `package.json`。

它写好的四条命令，连顺序都不用死记：

![npm run dev 之后：HyperFrames Studio 全貌](https://raw.githubusercontent.com/yeyangchen2009/draft-review/main/assets/hf02/hf02-studio.png)

*Studio 界面：左侧素材、中间预览、右侧检查器、底下时间轴上排着 Title 这条 clip*

| 命令 | 干什么 |
|---|---|
| `npm run dev` | 启动预览，浏览器里边改边看 |
| `npm run check` | 自动检查：lint、运行时、布局 |
| `npm run render` | 渲染成片 |
| `npm run publish` | 发布出去 |

这四步，正好就是上一篇念叨的那条主流程：**起项目 → 边写边看 → 把关 → 出片**。而且每一条命令都把版本钉死在 `0.8.107`，跟整个系列一模一样，绝不偷偷给你升级。

光说不看不行，叶扬跑了头一条 `npm run dev`。浏览器自动打开，就是上图这个 Studio：中间预览区是 init 给的那个最小页面——深色底，孤零零一行 Title，安安静静待在那儿。

别嫌它朴素。此刻你在 Studio 里看到的，已经是一条货真价实、十秒钟、随时能渲染成 MP4 的视频了。

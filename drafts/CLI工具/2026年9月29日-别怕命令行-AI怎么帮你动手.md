> 📖 这是"命令行工具箱"系列的第二篇。上一篇《命令行里的飞书》聊了飞书 CLI 怎么用，这篇退一步，回答一个更要紧的问题：这些看着吓人的命令行，到底是干嘛的？跟你又有什么关系？
> 不用懂编程，读完你也能跟别人讲明白：CLI、Skill、AI 这三者是怎么搭伙干活的。

# 先从一个抬杠的问题开始

"我又不是程序员，也没打算转行写代码，让我学这些黑乎乎的命令行，图啥？"

这问题问得特别好，叶扬第一次被人安利命令行时，心里也是这么顶回去的。但接下来要讲的事可能有点反直觉：**正因为 AI 来了，普通人反而更该知道命令行是怎么回事**，而且你几乎不用亲自敲它。

# 一、命令行，说白了就是"用打字指挥电脑"

平时用电脑，我们是**用鼠标点**：点一下文件夹、点一下保存。这叫图形界面，好处是看得见、点得准，坏处是你不点，它不动，而且一次只能点一两下。

命令行（行话叫 **CLI**，可以理解成"命令行工具"）换了个方式：**不画图了，直接用一句话告诉电脑要干嘛**。比如让它"把这个文件夹里所有照片名字改成今天日期"，一行字发出去，几百张照片唰一下全改好了。

打个比方：鼠标操作像在自动取款机上一个个按键，看得见摸得着；命令行像直接跟柜员说"把这一摞单子全办了"，前提是你得说对方听得懂的话。

# 二、AI 一来，命令行反而翻身了

命令行是个老东西，比鼠标还老，过去几十年一直是程序员的专属。普通人用不惯，卡在一个地方：**得记住那些冷冰冰的命令，记错一个字母就罢工**。

AI 把这道坎给铲平了。你不用记命令，只要说人话："帮我把这个表导成飞书多维表格。" AI 负责把这句话翻译成准确的命令，再交给命令行工具去执行。

于是分工变成了这样：

| 角色 | 它管什么 | 打个比方 |
|-|-|-|
| **你** | 说清想要什么 | 下馆子点菜的人 |
| **AI** | 听懂需求，决定怎么做 | 后厨里统筹的大厨 |
| **命令行 CLI** | 真正把活干出来 | 灶台上的锅和火 |

关键在最后一行：**AI 自己其实"摸"不到你的飞书、你的文档**。它能动起来，全靠命令行工具替它出手。没有趁手的工具，AI 就像一个厨艺满分、但厨房里一口锅都没有的大厨，只能干瞪眼。

# 三、三个平台，就配三个"遥控器"

叶扬日常用的平台有三个：飞书、AI 破局官网、知识星球。每个平台各自出了官方命令行工具，互不通用，就像电视、空调、机顶盒各有各的遥控器：

| 遥控器（CLI） | 管的是哪个平台 | 能帮你按出什么 |
|-|-|-|
| **lark-cli** | 飞书 | 建云文档、多维表格，查日历，发消息，走审批……飞书里能干的事它基本都能按 |
| **breakout-cli** | AI 破局官网 | 查官网主题、行动营、组局、勋章、AI 之心，目前以"看"为主 |
| **zsxq-cli** | 知识星球 | 发帖、评论、回答问题、记笔记、定时发布 |

有了对应的遥控器，你那句"帮我在飞书建个表"，AI 才真的够得着飞书。

# 四、Skill：贴在遥控器上的"说明书"

那 AI 怎么知道哪个遥控器管哪台设备、先按哪个键、按错了会怎样？靠的就是 **Skill**。

Skill 不是程序，**它自己一个手指头都不会动**。它是一份写给 AI 看的说明书：遇到什么需求、该用哪个工具、按什么顺序敲、有哪些不能碰的红线。比如飞书的 Skill 会告诉 AI："建表用这条命令，删东西是危险操作，得先问主人。"

到这儿，三个词就全串起来了：

> 🧠 **CLI 是动手的"遥控器"，Skill 是教 AI 用遥控器的"说明书"，AI 是那个边看说明书边替你按键的"人"。**

作为写代码出身的人，叶扬还想给这个比喻补一刀，因为**每个比喻都会在某个地方骗到你**：

- 遥控器要人按键才动，但这里真正"按键"的是 AI，不是你，这正是省事的地方；
- 说明书是写给人一句句读的，Skill 却是按"场景"触发的：AI 不用从头到尾背它，只要在你提出对应需求时，调出相关那一段照着办；
- 还有个大前提：遥控器得先装上电池、连上设备。换成这些工具，就是**得先安装、再登录授权**。没登录，说明书背得再熟，AI 也只会收到一句"没有权限"。

# 五、吵架现场：我点鼠标不就行了？

肯定有人不服："这些事我点鼠标也能干，干嘛绕一圈装工具、看说明书？"

这话对一半。偶尔干一次，点鼠标确实最快。但有两种情况，工具会甩开鼠标一大截：

- **重复的、批量的活**：整理 300 条数据、给 26 个学员逐份提交点评，手点要点到手酸，工具一行话、几分钟，还不会点错行；
- **想让 AI 替你干**：AI 只会使唤那些带命令行的工具。你想用一句话把活派给它，就得给它配好遥控器，否则它帮不上。

所以不是"命令行取代鼠标"，而是**各管一段**：偶尔点一下的小事用鼠标，重复的、想交给 AI 的事用工具。

# 六、卡壳角：叶扬踩过的两个坑

别以为装了工具就一马平川，叶扬自己也栽过：

- **坑一：以为装完 CLI 就完事了。**结果第一次让它干活，冷冰冰一句"请先登录"。安装只是把遥控器买回来，登录授权才是装上电池，两步都不能省。
- **坑二：以为有了官网工具，就能自动给学员打卡打分。**兴冲冲去查，发现官方目前只开放了"看"的能力，提交评分这种"写"的操作还没放出来。所以打分这一步，暂时还得靠浏览器模拟来做。这也提醒一件事：**工具有没有那本事，要查它实际开放了哪些能力，不能想当然。**

# 术语小抄

| 术语 | 大白话 |
|-|-|
| CLI / 命令行工具 | 用一句命令让电脑批量干活的"遥控器" |
| AI Agent | 能听懂你说话、还会调工具替你动手的 AI 助手 |
| Skill | 写给 AI 看的工具说明书，自己不动手 |
| 登录 / 授权 | 给遥控器装电池，让它够得着你的账号 |
| 只读 / 写入 | 只能"看"，还是能"改"；能改的操作更危险，通常要先问你 |

留个小问题给你：如果哪天你想让 AI 帮你整理一份飞书表格，对照上面的三个角色想想，你会先确认哪两样东西已经准备好了？想清楚这个，你就真的把这套机制吃透了。

想亲自上手安装、或者好奇"一份说明书怎么同时给好几个 AI 用"，文末附录里有不藏私的操作步骤，胆大的可以接着往下翻。

## 安装与登录

```bash
# 飞书 / 知识星球 CLI 都在 npm，全局安装（需 Node 16 以上）
# 注意飞书的包名带 @larksuite 前缀，装出来的命令才是 lark-cli
npm install -g @larksuite/cli zsxq-cli

# 破局官网 CLI 是独立程序、不在 npm，按官网方式安装；自更新：
breakout-cli update

# 各工具第一次使用分别登录
breakout-cli auth login
```

## 一份说明书，多个 AI 共用

并没有"所有 AI 通用"的文件夹，每个 AI 只读自己的那一份。叶扬的做法是：把正本放在一个中立目录，再用 Windows 的"目录联接"（可以理解成给同一个文件夹开好几扇门）挂进每个 AI 的目录。改一处，处处生效，不用复制好几份。

```bash
# 破局 skill 的文字内嵌在程序里，只能由工具导出
breakout-cli integrate codex

# 归到中立正本目录后，用目录联接挂给某个 AI（路径用反斜杠，免管理员权限）
cmd /c mklink /J "C:\Users\你的用户名\.claude\skills\breakout-official-cli" ^
                 "C:\Users\你的用户名\.agents\skills\breakout-official-cli"
```

本文截图中的 `username` 是占位写法，实际操作时换成你自己的 Windows 用户名即可。
